# Этап 12 — включение MCP-configurator в линию разработки

Ред. 1, 24.10.2026. Предпосылки: сервер собран (этапы 2–6, «Доводки», «Проба хранилища»,
«Конструкторы»), Снегопат 1.6.40, приёмка e2e 28/28. Родственные этапы: 8 (поддержка) и
9 (cf+объединение) — они научили ЛИНИЮ быстро принимать cf; этот этап замыкает звено
«агент поправил живую базу → cf → линия».

## 1. Целевая цепочка

```
агент (MCP)                      линия выпуска (пакетный контур, kit 0.3.23+)
───────                          ─────────────────────────────────────────────
непривязанная живая база-макет
md_add_child / module_set /
md_set_synonym / md_set_type
   │ config_save (архив cf — точка отката)
   ▼
cfg_archive_cf ──→ поставка.cf ──→ /MergeCfg или /LoadCfg в базу слота
                                   → /UpdateDBCfg
                                   → постусловие: частичная выгрузка (-listFile)
```

Место MCP — живая станция (инвариант 9 плана: не на CI/раннерах). База-макет —
непривязанная (ограничение 25.10.2026: на привязанной Insert/Delete не работают).
cf из живой конфигурации снимается штатной командой «Сохранить конфигурацию в файл»
(внутренний `saveToFile` на 2074 не работает — спайк).

## 2. Этапы и критерии

- [x] **П1. Живая правка → cf.** В непривязанной базе создать объект с наполнением
  (справочник + реквизиты с типами + синонимы, модуль), сохранить, снять cf.
  **Критерий:** cf существует, размер правдоподобен; объект в живой базе сверён
  обратным чтением. *(24.10.2026: пройден — модуль в этой пробе не задействован, типы
  через md_set_type; модули проверены в e2e)*
- [x] **П2. cf → база линии.** Пакетным конфигуратором: свежая база → `/LoadCfg`
  поставка.cf → `/UpdateDBCfg` → частичная выгрузка объекта `-listFile`.
  **Критерий:** вердикт — постусловием (объект есть, реквизиты/типы совпали с живой
  базой), не кодом возврата; `/DumpResult` = 0. *(24.10.2026: пройден последовательно;
  склейка команд в один вызов — висит, см. находку в §3)*
- [x] **П3. Тишина вендорских объектов.** cf живой базы увозит ВСЁ её состояние
  (урок этапа 9 про «DumpCfg из базы сборки»): сверить, что в базу линии не уехало
  ничего, кроме созданного (сравнение частичных выгрузок базовой пары объектов).
  **Критерий:** до/после — различие ровно в созданных объектах. *(24.10.2026: пройден —
  полная выгрузка базы линии содержит только созданный объект)*
- [ ] **П4. Связка с волной (вне пробы, решение владельца).** cf-источник для
  `/MergeCfg -Settings` из живой базы — как альтернатива сборке cf полной загрузкой
  XML из дерева HEAD (kit 0.3.23, `wave_ops build-cf`). Требует наработки на базе
  линии — отдельно.

Замеры и результаты — в разделе 3 (заполняется по ходу проб).

## 6. Л1 — обёртка handoff (24.10.2026, сделано)

`server/tools/mcp_to_line.py` — одна команда: cf из живой базы → база линии →
постусловие. Шаги: живая сессия именно этой базы (сверка строки соединения) →
config_save при изменениях (архив cf — точка отката) → `cfg_archive_cf` →
последовательные `/LoadCfg` → `/UpdateDBCfg` → `/DumpConfigToFiles -listFile` →
постусловие «каждый объект из списка есть в выгрузке». Вердикт каждого шага: код
возврата + `/DumpResult` + фатальные фразы лога.

| Прогон | Итог |
|---|---|
| Позитив (`--objects Справочник.МсрЛинТовары`) | **7/7, exit=0** (отчёт `verify/mcp_to_line/handoff-20261024-153208.json`) |
| Негатив (`--objects Справочник.НеТакой`) | быстрый отказ на `DumpConfigToFiles` кодом 1, exit=1, без модальных окон |

**Ловушка (из негативной пробы):** без `/DisableStartupDialogs` пакетная команда на
ошибке `-listFile` поднимает МОДАЛЬНОЕ окно «Объект метаданных … не существует» и
висит вечно — в инструмент ключ добавлен во все вызовы. Отличать от ловушки
«конфигуратор без ключа не поднимает Снегопат»: живой конфигуратор запускается БЕЗ
ключа, пакетные вызовы — всегда С ним. Ещё две мелочи эксплуатации: стартёр должен
быть запущен ДО старта конфигуратора (иначе мост не внедрится и обёртка не найдёт
сессию); exit-код обёртки не читать через пайп (`| tail` маскирует).

Дальше: Л2 — проба cf из макета на реальном слоте линии (координатор), Л3 — сценарий
чистого макета, Л4 — регламент агента в скиле.

## 4. Ограничения

* Live-база и база линии — РАЗНЫЕ каталоги; пакетный конфигуратор не может открыть
  базу, удерживаемую живым конфигуратором.
* cf живой базы — снимок ВСЕЙ конфигурации: база-макет должна быть чистой (без чужих
  опытов), иначе в линию уедет лишнее (см. П3).
* Структурные правки — только непривязанная база; правки существующего на привязанной
  — после захвата (этап «Проба хранилища»).

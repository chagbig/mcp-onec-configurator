# Этап 22: отладка (точки останова), поиск по модулям, структура модуля (09–10.11.2026)

Три подпункта этапа 2: ① проба отладки → рабочий рецепт, ② IDEAS №15
md_search_code (50-й инструмент), ③ IDEAS №16 module_structure (51-й).
② и ③ выполнены параллельными агентами; интеграция, живые смоуки и релиз —
основной сессией. 128/128 тестов. Версия v1.2.5.

## ① Отладка конфигуратора — точки останова через Снегопат

Полная хроника проб — `docs/debug-brkpt-probe.md` (коммиты b22e360, e98e96f).
Ключевое:

- **Группа CDebug** доступна аддинам (`stdcommands.CDebug`, живой скан 10 команд),
  НО `sendCommand(CDebug.Brkpt)` из тика моста **блокирует тик** нативным
  ожиданием без pump (2 зависания, только taskkill) — диспетч-путь для курсорных
  команд запрещён навсегда (гард в `send_debug_cmd`);
- **Рабочий путь — F9 через PostMessage** (DWX `PostMessageW`; SendMessage идёт
  мимо таблицы акселераторов);
- **Точки ставятся по конфигурации БД** — подсказка владельца раскрыла главную
  ловушку: `module_set → config_save → update_db_cfg → OpenModule → F9`; без
  update_db_cfg модалка «строка отсутствует в сохранённой копии» (снаружи
  некликабельна — диалог 1С не энумеруется ни топ-левел, ни как child);
- **Точное позиционирование** — `snegopat.activeTextWindow().setCaretPos(row,col)`
  (ITextWindow, обкатано в BookMarkers/textEditorExt); стрелки через SendMessage
  каретку не ведут (маркер встал на пустую строку EOF — подтверждено владельцем:
  «красный маркер есть, только это пустая строка»);
- ops моста: `send_debug_cmd` (белый список + гард активного вида),
  `editor_caret` (чтение/установка каретки), `editor_brkpt_toggle({line})`,
  `editor_brkpt_state`;
- `checked` команды «Точка останова» точку не отражает; панель «Точки останова»
  — немодальная нативная сетка (onDoModal не ловит, view_controls даёт
  «Предполагается наличие объекта») — чтение списка отложено отдельной разведкой;
- верификация установки — визуальная (владелец подтвердил маркер); схема остаётся:
  агент ГОТОВИТ точки, человек ведёт отладку (kExecutionStateEvent без обёртки).

## ② md_search_code — поиск по текстам модулей (50-й инструмент)

`server/tools/md_search_code.py` + MCP `md_search_code(query, cf_path, regex, limit)`.
Без платформы: cf от `cfg_archive_cf` читается cf_inspect, тексты модулей —
страницы **text** в `.0`-сериализациях объектов (контейнер модуля: utf-16 маркер
«text», заголовок страницы, содержимое ограничено полем size), uuid записи =
uuid объекта, имена из `{1,0,<uuid>},"Имя",` (202 имён на демо-cf).

Разведка установила (пробы в probe/): записи модулей на 8.3.27 — НЕ `.2`
(суффиксы .1 = шаблоны пустых модулей); текст лежит ПОСЛЕ заголовка страницы;
в хвосте страницы — сталь прежних сохранений (у «опустевших» модулей size=3 =
BOM, а хвост содержит копию старого текста) — содержимое ограничивается полем
size, иначе ложные попадания. Строки модуля разделены `\r\r\n`.

Агент A переписал нерабочий черновик целиком (обход блоков вложенного
контейнера cf_inspect, отбрасывание стали, счёт строк от начала содержимого).
12 юнит-тестов (8 синтетических на search_record + 4 живых skipUnless) + 106
регресса. Живая верификация: «Сообщить("Создание элемента» → **Эмитенты, строка
2, колонка 1** (побайтовая сверка текста), «Сумма расчёта» → РасчётСКлиентом:9,
`--regex 'Сообщить\('` → 9 попаданий в 6 объектах.

Семантика: поиск по **сохранённой** конфигурации (архив до config_save не
содержит module_set — проверено). Сценарий: `cfg_archive_cf → md_search_code` —
«где вызывается Процедура X» по всей конфигурации за секунды.

## ③ module_structure — структура модуля (51-й инструмент)

`server/tools/module_structure.py` (агент B): `parse(text)` — блоки
Процедура/Функция с line_start/line_end, директивами (&НаСервере… с привязкой
вверх через пустые строки/комментарии), Экспорт, параметрами; `find_call_sites`
— вызовы процедуры в модуле (объявление/Конец/доступ через точку исключены,
регистронезависимо). Эвристика MVP задокументирована (начало строки + «(»;
полный лексер не нужен).

MCP `module_structure(session, container, path, prop, calls_of)` — живой
module_get(withText) → parse. **Ловушка интеграции: параметр моста — `withText`
(camelCase), `with_text` молча возвращает text=None** (пойман живым смоуком:
0 блоков при непустом модуле). Живой смоук Эмитенты: 2 блока (строки 1–3,
5–7), вызовы на строках 2 и 6 — точное совпадение с эталоном.

10 юнит-тестов (комментарии со словом «Процедура», LF-only, незакрытые блоки,
«Функция» без «(», директивы через пустые строки).

## Порядок работ и уроки

- Разделение на агентов: ② и ③ параллельно, агенты НЕ трогают server.py —
  интеграция одной рукой после (без конфликтов правок); оба агента получили
  запрет на коммиты и ограничение консоли cp866 (вывод в UTF-8 файлы).
- Общий регресс 128/128; живые смоуки обоих инструментов через MCP-путь
  (Toolkit) перед релизом.
- Ловушка параметров моста: camelCase (withText, openEditor) — snake_case
  молча игнорируется.

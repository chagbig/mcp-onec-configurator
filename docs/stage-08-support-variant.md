# Этап 8 — добавление объектов в конфигурацию НА ПОДДЕРЖКЕ (17.10.2026)

## Замер (итог, проба завершена)

Добавление одного справочника в ERP `УправлениеПредприятием` 2.5.17.95 (копия 5 ГБ, 8.3.27.2074):

| Способ | Шаги и время | Итог |
|---|---|---|
| **B — новый (cf + объединение)** | объединение cf 247–499 c + `update-dbcfg` 48 c | **≈ 5–10 минут** |
| **A — текущий (полная загрузка XML)** | полная загрузка ~90 тыс. файлов + `update-dbcfg` | **≈ 2,5 часа** (подтверждено боевой линией; полная выгрузка XML одна — 1,9 ч) |

Вывод: cf+объединение дешевле полной XML-загрузки на порядок. Способ B принят.

## Критическая ловушка (проверено)

Конфигурация НА ПОДДЕРЖКЕ с запретом изменения: объединение (и загрузка) даёт код 0,
«успешно завершено», но **не вносит НИЧЕГО**. Вердикт — только постусловием (частичная
выгрузка объекта), не по коду возврата. ERP была на поддержке → ноль; БСП снята → объект приезжает.

## Модель поддержки (решение владельца 17.10.2026)

1. **Добавление новых объектов** — включить «возможность изменения» ВСЕЙ конфигурации
   С СОХРАНЕНИЕМ поддержки. Новые объекты — свои, поставщика не трогают.
2. **Доработка объекта поставщика** (добавить реквизит) — снять ЭТОТ объект с поддержки
   **с возможностью обновления** (`editable`: правки свободны, обновления вендора продолжают приходить).

Параметры (в `Ext/ParentConfigurations.bin` выгрузки — ТЕКСТ с BOM, заголовок `{6,G,K,<guid>…`; скил `support-edit`):
- **возможность изменения (глобально) — флаг `G`: `0` ВКЛючена (объекты добавляемы, поставщик на замке), `1` ВЫКЛючена (вся конфа read-only).** Проверено: `support-edit -Capability on` на реальном бине ERP сменил `{6,1,1,…}` → `{6,0,1,…}`.
- правило объекта `<F1>,0,<uuid>`: `0` на замке, `1` editable (правки + обновления вендора идут), `2` снят с поддержки (обновления прекращаются).
- реальная ERP `УправлениеПредприятием` была `{6,1,1,…}` → G=1 → read-only → объединение/загрузка молча не вносили НИЧЕГО (код 0, «успешно»).

**Ограничение батч-фикстуры:** `/MergeCfg <distrib> -EnableSupport` распознаётся (на обычном cf: «Возможность … постановкой на поддержку отсутствует»; на дистрибутиве: «Обнаружена возможность…»), но ставит на поддержку только при настроенном каталоге шаблонов конфигураций (иначе «Каталог не обнаружен ''»). То есть постановка НА поддержку в чистом пакетном окружении требует env-настройки или живого конфигуратора. Снятие с поддержки и переключение `G`/`F1` — через `support-edit` по выгрузке, применяется загрузкой.

## Этапы проб на тестовой базе (пустая конфигурация)

Фикстура:
- **F1.** Пустая конфигурация → создать `Справочник.Объект1` (2 реквизита) → сохранить → cf «релиз1» (роль вендора).
- **F2.** Чистая база → загрузить релиз1 → поставить НА поддержку: `/CreateDistributionFiles` → `/MergeCfg -EnableSupport`.
  Постусловие: появился `Ext/ParentConfigurations.bin`, `Объект1` на замке.

Проба 1 — добавить новый `Объект2` в конфигурацию на поддержке (быстрый вариант):
- **P1.1** включить возможность изменения (Capability on) с сохранением поддержки;
- **P1.2** собрать `Объект2` в отдельной пустой конфе → cf;
- **P1.3** `/MergeCfg объект2.cf -Settings` (корень DoNotMerge + `Объект2` GetFromSecondConfiguration) → `/UpdateDBCfg`;
- **P1.4** постусловие: `Объект2` есть (частичная выгрузка), `Объект1` по-прежнему на поддержке, замок цел.

Проба 2 — снять `Объект1` с поддержки с возможностью обновления:
- **P2.1** `support-edit -Path Объект1 -Set editable` (F1=1) → применить;
- **P2.2** постусловие: `Объект1` редактируем, связь с вендором сохранена.

Проба 3 — изменить `Объект1` (добавить реквизит):
- **P3.1** добавить реквизит в `Объект1` → применить;
- **P3.2** постусловие: реквизит есть, отказа по поддержке нет.

Подбирается: можно ли применить правку правила поддержки и реквизита ЧАСТИЧНОЙ загрузкой
(объект существует) без полной; точные значения флагов на реальной фикстуре.

## Куда включить

1. **Скилы**
   - `support-edit` — добавить рецепты «возможность изменения ON → merge» и фикстуру «поставить на поддержку»; сверить флаги на реальной пробе.
   - `onec-configurator-bridge` — раздел «Добавление нового объекта в конфигурацию НА ПОДДЕРЖКЕ (быстрый вариант)»: включить изменение → cf+merge → update-dbcfg; таблица замера 10 мин vs 2,5 ч; смягчить нынешнее «поддержку не трогаем» до управляемого рецепта.
2. **bridge** (`scripts/onec_bridge.py`)
   - `merge-cfg --file --settings` с постусловием (частичная выгрузка объекта), а не только код возврата;
   - `manage-support --on-support <distrib> | --capability on|off | --object <name> --set editable|off-support|locked`.
3. **KIT** (`ci/tools/onec_bridge.py` + обвязка)
   - операция «добавить новый объект в конфигурацию на поддержке» для линии выпуска: cf+merge, постусловие частичной выгрузкой, тайминг в отчёте/стороже.

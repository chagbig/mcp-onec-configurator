# Проба: точки останова через Снегопат (09.11.2026)

Вопрос владельца: «Возможно ли делать точки остановки при отладке в конфигураторе
через snegopat?». Живая проба на empty2 (1.6.43, Снегопат 3.0.66-стартер недоступен
днём — проба на 1.6.43; группа и команды совпадают).

## Что доказано

1. **Группа «Отладчик» доступна аддинам**: `stdcommands.CDebug` (commands.js:148,
   группа `{DE680E96-5826-4E22-834D-692E307A1D9C}`) — полный набор: Начать отладку (2),
   Шагнуть в/через/из (6-8), Идти до курсора (9), **Точка останова (11)**, Точка с
   условием (12), Отключить (13), Убрать все (14), Список точек (16), Табло (18),
   Стек вызовов (19), Остановка при ошибке (21), Локальные переменные (28).
   Стоковый `debugHelpers.js` шлёт Brkpt/BrkptDel живьём. Живой скан группы:
   10 команд отвечают enabled=true (без открытого модуля).

2. **Мост не может послать Brkpt диспетчем**: `sendCommand(CDebug, 11)` из тика
   моста БЛОКИРУЕТ тик нативным ожиданием без pump (CPU 0, модалки нет, выход
   только taskkill) — два прогона, в т.ч. при активном редакторе модуля.
   Навигационные/оконные команды при этом безопасны (OpenModule Frntend,11 — ок).

3. **Рабочий путь — F9 через PostMessage** (DWX `PostMessageW`, в snegopat
   winapi.js не зарегистрирован; SendMessage идёт мимо таблицы акселераторов).
   F9 дошёл до команды — и вскрыл ГЛАВНОЕ правило:

4. **«Нельзя установить точку останова в строке, которая отсутствует в
   сохранённой копии»** (скриншот владельца): точка ставится по СОХРАНЁННОЙ
   конфигурации. Модуль, дописанный module_set без config_save, точек не
   принимает — конфигуратор показывает модалку, которая блокирует тик моста
   (снаружи не кликается: диалог не #32770 и не топ-левел; SendKeys к 1cv8
   запрещён). Следствие: **config_save ДО постановки точек — обязательный шаг**.

## Ops моста (добавлены, помечены как пробные)

- `send_debug_cmd(cmd)` — белый список: OpenModule (Frntend,11), Brkpt/BrkptCond/
  BrkptOff/BrkptDel/BrkptOffAll/BrkptList/BreakOnError/GoToSource (CDebug) с
  гар­дом «активный вид = редактор модуля» для курсорных; до/после состояние
  команды (checked у Brkpt отражает точку на текущей строке). ⚠️ Brkpt/BrkptCond/
  BrkptOff/GoToSource через диспетч ЗАПРЕЩЕНЫ к использованию (блок тика) — гард
  их не спасает, безопасен только F9-путь.
- `editor_brkpt_toggle({down:N})` — курсор вниз на N строк (SendMessage, inline в
  scintilla, безопасно) + F9 PostMessage (DWX); возвращает до-состояние.
- `editor_brkpt_state()` — состояние точки на текущей строке без переключения.
- `dialog_probe` расширен группой `debug` (nums 16, 21 — список точек, остановка
  при ошибке).

## Подтверждённый рецепт (09.11, вторая половина пробы)

Модалка «строка отсутствует в сохранённой копии» ставит точки в зависимость от
**конфигурации БД** (по ней ведётся отладка) — подсказка владельца («если
конфигурацию сохранить — модалки не будет») раскрыла недостающий шаг:

```
module_set (код)  ->  config_save  ->  update_db_cfg  ->  OpenModule  ->  F9 (PostMessage)
                                            ^^^^^^^^^^^^^
                                            БЕЗ этого шага БД-копия пуста и модалка
                                            блокирует тик (два зависания, taskkill)
```

- после цепочки с update_db_cfg (62 мс, без диалогов) F9 **не блокирует** —
  сессия отвечает (3 мс);
- `checked` команды «Точка останова» точку НЕ отражает (остался false);
- «Список точек останова» (CDebug,16) — НЕМОДАЛЬНАЯ панель «Точки останова»
  (onDoModal не ловит, view_controls даёт «Предполагается наличие объекта») —
  чтение списка точек требует отдельной разведки панели;
- финальная верификация установленной точки — визуальная (панель/красный
  маркер в редакторе открыты на экране владельца).

## Осталось (кандидат этапа)

- Верификация полного круга: config_save → OpenModule → F9 → checked=true →
  диалог «Список точек останова» (dialog_probe debug,16) показывает точки.
- Проверка на 3.0.66 (группа сканом подтвердилась там же ранее).
- Позиционирование курсора на произвольную строку (Ctrl+G-диалог или построчный
  Down) + условные точки (BrkptCond-диалог через wizard-механику).
- Ход отладки агенту недоступен: событие останова (kExecutionStateEvent в
  debugger.v — только GUID) SnegAPI не отдаёт; команды «Шагнуть» слать можно,
  но «остановился на строке N» мост не видит. Схема: агент ГОТОВИТ отладку
  (точки по сохранённой конфигурации), человек запускает и ведёт.

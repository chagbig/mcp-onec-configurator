# Этап 8 — раскладка форм в XML через временную базу (план реализации, ред. 1)

26.10.2026. Исходные решения — `docs/plan-mcp-snegopat.md` §5 этап 8 и §3.1; первичка —
`docs/spike-01-demossl.md` (опыт 4а), `docs/stage-02-06-mcp-server.md`. Приёмка по правилу
«вердикт — постусловием».

## 1. Цель

Агент читает и правит **раскладку форм живой конфигурации в XML** (формат скилов
`form-edit`/`form-validate`/`form-compile`) — через временную базу, без реверса и без
правки движка. Мост уже даёт: внутренний текст живой формы при открытом редакторе
(`form_save` c хешем, `form_load` с expected_hash — ревью 25.10).

## 2. Установленные факты (первичка)

| Факт | Источник |
|---|---|
| Внутренний текст живой формы читается/пишется ТОЛЬКО через открытый редактор (`editProperty` → `getExtProp.saveToFile/loadFromFile`, UTF-8 BOM) | спайк 4а, этап «Доводки» |
| `loadFromFile` применяет правку; круг устойчив; `isModified` контейнера НЕ выставляется | спайк 4а |
| Пакетный конфигуратор переводит XML↔внутренний ТОЛЬКО при `/LoadConfigFromFiles` и `/DumpConfigToFiles` конфигурации; отдельный внутренний текст он не грузит | план §3.1 |
| `container.saveToFile` (cf через API) на 8.3.27.2074 не работает; cf снимается штатной командой (`cfg_archive_cf`) | спайк опыт 1 |
| `v8files.attachStorage` (распаковка записей cf) — существование известно, поведение на cf не проверено | план §5 (вопрос этапа 8) |
| Скилы `form-edit`/`form-validate` работают с XML; формы в выгрузке — `Forms/Form/Ext/Form.xml` | скилы |
| `form_save` возвращает хеш внутреннего текста; `form_load` требует `expected_hash` | ревью 25.10 |

## 3. Архитектура

### 3.1. Чтение (живая форма → XML) — ред. 2 (К1, М2 ревью Kimi)

```
если контейнер isModified=true → ОТКАЗ «есть несохранённые правки — чтение отражает
только сохранённое состояние» (без побочных действий; config_save в чтении ЗАПРЕЩЁН —
он бы тихо закрепил чужие несохранённые правки человека, К1)
cf последнего сохранённого состояния (cfg_archive_cf, кэш cf по времени)
temp_read (раз на cf, mockup_init --from): /DumpConfigToFiles -listFile
(Документ.X.Form.Y) → XML формы
```

* Кэш **безусловный** `form_hash → XML` (М2): XML управляемой формы самодостаточен,
  внешние зависимости — ссылки по uuid, стабильные. Чужие сохранения не инвалидируют
  кэш; пересборка temp_read — только для формы, которой нет в кэше, на свежем cf.
* Свежесть формы против cf (К1): хеш живого текста (`form_save`) против текста из cf
  (`cf_extract_text`) с **шапка-нормализатором из П1** — расхождение = несохранённая
  правка этой формы → отказ (XML отражает cf).
* Ловушка: cf = последнее СОХРАНЁННОЕ состояние («Нет» на вопрос об изменениях).

### 3.2. Запись (XML → живая форма) — ред. 2 (К2, М1, М3, М5 ревью Kimi)

```
предусловие: контейнер isModified=false; снимок состава владельца формы
(реквизиты/ТЧ/имена) в живой базе == снимку на момент чтения XML (К2: Identifier
не ловит удалённый реквизит); form-validate XML (скилом, вне сервера)
temp_write (ОТДЕЛЬНАЯ база записи, пересобирается из свежего cf на КАЖДУЮ запись —
после /LoadConfigFromFiles temp считается загрязнённой, М3):
  /LoadConfigFromFiles -listFile (правленный XML, Configuration.xml НЕ включать)
  ПОСТУСЛОВИЕ (М5): /DumpConfigToFiles этой формы из temp → XML ПОБАЙТНО равен
  правленому (иначе отказ ДО /DumpCfg — загрузка не сработала)
  /DumpCfg temp_write → cf2
РАСПАКОВКА cf2 (П1/М4): внутренний текст правленной формы → живой редактор
  (view_activate + form_import): postcondition loaded===true (иначе отказ, М5) +
  expected_hash текущего состояния
отметить изменение (способ — проба П3) → config_save
ВЕРИФИКАЦИЯ (М1 — дёшево, без второго config_save и полного круга):
  (а) form_save.hash живой == hash текста формы из cf2 (с шапка-нормализатором)
  (б) XML этой формы, выгруженный из temp_write, ПОБАЙТНО равен правленому (L3)
  расхождение → полный круг §3.1 как диагностика
```

* Критическая зависимость записи — **распаковка cf** (проба П1). Если attachStorage
  не распакует записи cf: реверс не делаем; этап закрывается «чтение сдано, запись —
  после решения владельца»… до пробы не гадаем.
* `isModified` после `form_import` не выставляется (спайк). Кандидаты: безопасное
  изменение свойства владельца туда-обратно; либо сохранение из редактора формы.
  Выбирается пробой П3; config_save без isModified=false — отказ (уже так).

## 4. Пробы и критерии

| № | Проба | Критерий (ред. 2 — М4/М5/М6/К2) |
|---|---|---|
| **П1** | `v8files.open(cf).attachStorage` на cf empty2 (80 КБ): перечислить записи (find), открыть, извлечь текст формы; затем **то же на cf2 пробного круга** и **на боевой форме ГисМарк с картинкой/вложенным макетом** (mockup-gm — М4: empty2 это не проверит) | (а) записи cf видны; (б) текст формы извлечён; (в) **снята карта отличий «cf-текст vs form_save-текст»** — что именно в «шапке состояния редактора», построен нормализатор, нормализованные хеши равны; (г) точная процедура записи файла для `loadFromFile` (UTF-8+BOM) проверена обратным `form_load`. Отрицательный исход (а/б) = запись не реализуема без реверса — решение владельцу |
| **П2** | Чтение-круг на макете ГисМарк (`mockup-gm`): cf → temp_read → XML боевой формы; **замер Config.Save и cfg_archive_cf на cf 2 ГБ (недостающий факт, L1)** | XML получен; круг замерен (факт вместо критерия «≤10 мин»); точечная сверка XML против внутреннего текста |
| **П3** | Запись-круг на empty2: XML → тривиальная правка → цепочка §3.2 (постусловие dump==правленый и loaded=true) → config_save → верификация (а)+(б) | правка в XML верификации; **негатив К2**: между чтением и записью удалить реквизит владельца → отказ до form_import; способ отметки isModified подтверждён |
| **П4** | Приёмка на макете ГисМарк (конфигурация из cf — НЕ на поддержке, М6): правка на копии боевой формы | как П3 + счёт элементов XML (ничего не потеряно); **негатив К2**; скоуп зафиксирован в доке |

Единица правки для приёмки — свойство существующего элемента (заголовок) и добавление
элемента; «перетащить/удалить половину формы» вне приёмки. **Скоуп (М6): основная
конфигурация; расширения и формы на поддержке — вне этапа 8** (боевые формы ГисМарк
на поддержке — отдельное решение владельцу).

## 5. Реализация (после проб)

| Что | Где |
|---|---|
| `form_get_xml(session, path, prop, temp_base)` — оркестрация §3.1 с кэшем по hash; temp-база поднимается `mockup_init --from cf` при первом чтении | `server/tools/` или Toolkit |
| `form_set_xml(session, path, prop, xml, temp_base, expected_hash)` — цепочка §3.2; validation — вызывающий (скил form-validate) | туда же |
| Мост: op `cf_extract_text(cf, mask)` — перечисление записей attachStorage и извлечение текста (после П1) | `bridge/mcp_bridge.js` |
| Очистка/переиспользование временных баз; лимит одновременных; лог цепочки | server |

Правило инвариантов: все записи — с expected_hash; верификация — постусловием
(повторное чтение); конфигурация не сохраняется без cfg_archive_cf.

## 6. Риски

| Риск | Что делаем (ред. 2) |
|---|---|
| attachStorage не читает cf (П1) | запись не реализуема без реверса — останов, решение владельцу; чтение всё равно сдаётся |
| **config_save в чтении закрепит чужие правки (К1)** | УСТРАНЕНО: config_save из чтения убран; при isModified=true — отказ чтению |
| **Ссылки формы на удалённые объекты (К2)** | снимок состава владельца при чтении, сверка при записи + негативы в П3/П4 |
| Temp_write загрязнена после /LoadConfigFromFiles (М3) | пересборка на каждую запись; temp_read — отдельная база, не трогаем |
| Молчаливый loaded=false (М5) | postcondition loaded===true + dump==правленый до /DumpCfg |
| Шапка редактора — ложные отказы/успехи (М4) | нормализатор строится в П1; верификация — нормализованные хеши + побайтовое сравнение dump (L3) |
| Форма-миллионник (ГисМарк) | замер в П2 (Config.Save/cfg_archive_cf на 2 ГБ — недостающий факт); кэш безусловный (М2) |
| isModified-ловушка | проба П3 выбирает способ отметки; config_save без isModified=false — отказ (уже так) |
| Расширения/поддержка (М6) | вне скоупа этапа 8, зафиксировано; П4 на макете |
| Диск (L2) | temp_read + temp_write + cf + cf2 ≈ 4×2 ГБ на ГисМарк — в очистке |

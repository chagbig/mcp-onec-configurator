# Этап 13. Расширения конфигурации (план, ред. 1 — 28.10.2026)

## 1. Цель

Агент работает с расширениями конфигурации в живом конфигураторе: создать/удалить
расширение, читать и менять его дерево, модули и свойства, заимствовать объекты,
сохранять/загружать .cfe, включать cfe в линию. Формы расширения — отдельное решение
по итогам проб (см. вне скоупа): контур этапа 8 грузит cf ОСНОВНОЙ конфигурации и к
расширению неприменим без отдельного cfe-контура (ревью К-1).

## 2. Скоуп

**В скоупе:** свои (неприсоединённые) расширения; живой конфигуратор как основной путь;
пакетный путь — только для переноса cfe/выгрузок в линию; расширения своей разработки.

**Вне скоупа (как М6 в этапе 8):** присоединённые (вендорские) расширения и снятие с
поддержки; тонкий/веб-клиент; расширения других баз; **запись форм расширения**
(нужен отдельный cfe-контур, ревью К-1); перехватчики методов и снятие контроля
заимствованных объектов (собственные диалоги платформы); безопасный/привилегированный
режим расширений; расширения в составе поставки; применение расширений к конфигурации
БД (нужен ли шаг обновления БД для расширений — недостающий факт, закрывается пробой П5).

## 3. Текущее состояние и главная гипотеза

Мост адресует метаданные через `container(args.container)` — `session_info` уже
показывает контейнеры («Конфигурация базы данных», «Основная конфигурация», …).
Движок Снегопата (`metadata.openedCount`, `getContainer(i)`) видит ВСЕ открытые
контейнеры — расширение после открытия в конфигураторе должно появиться контейнером.

**Г1 (главная гипотеза):** расширение = обычный контейнер; существующие операции
(md_tree/md_object/md_children/module_get/module_set/md_add_child/form_export)
работают на нём через `container=N` без правок моста. Тогда серверу нужны только
операции ЖИЗНЕННОГО ЦИКЛА расширения.

**Г2 (ПОНИЖЕНА до открытого вопроса, ревью К-1):** чтение формы расширения
(form_export) должно работать как у основной — проверяется в П3; ЗАПИСЬ форм
расширения существующим контуром НЕВОЗМОЖНА (cf основной конфигурации не содержит
расширений, cfg_load_cf меняет основную) — вне скоупа до отдельного cfe-контура.

## 4. Архитектура (после проб)

| Что | Где |
|---|---|
| `ext_list(session)` — расширения живой сессии: имя, контейнер, isModified | server (session_info; видит только ОТКРЫТЫЕ контейнеры — ревью М-4) |
| `ext_open(session, name)` — открыть дерево расширения (если не открыто) | мост/сервер — операция жизненного цикла (ревью М-4) |
| `ext_create(session, name, prefix, synonym)` — создать расширение | мост (штатная команда + диалоги через перехват/мастер-раннер) |
| `ext_save(session, name)` — штатное «Сохранить» расширения; постусловие isModified=false | мост (ревью М-3: без него правки module_set/prop_set не закрепить) |
| `ext_save_cfe(session, name, file)` / `ext_load_cfe(session, name, file)` | мост; ext_save_cfe — ТОЧКА ОТКАТА, семантика как cfg_archive_cf: при isModified отвечает «Нет» — в cfe уходит последнее сохранённое (ревью L-3) |
| `ext_delete(session, name)` | мост; подтверждение удаления — в белом списке явно; предусловие: редакторы расширения закрыты (ревью М-5) |
| `ext_borrow(session, container, objects)` — заимствование из основной | мост (команда Frntend,271 «Добавить в расширение»); модальность диалога — отдельная проба П4а (ревью М-6) |
| Прокидывание `container` в существующие op | server (частично уже есть) |
| Пакетный путь линии: -Extension ключи дизайнера | tools/ — П6-разведка справки + ручной перенос cfe (ревью К-2) |

Инварианты этапа (ревью М-1, М-7):
1. Запись в расширение — только после резолва «имя расширения → индекс контейнера»
   СВЕЖИМ session_info в момент операции + **uuid обязателен** (контейнеры плавают,
   ошибка адресации = порча основной конфигурации).
2. Все новые capture-переменные ext-операций вносятся в guard-список onWizardModal
   (`stgCapture || updCapture || … || extCapture`), иначе мастер-раннер кликает чужие
   диалоги расширений.

Правила инвариантов сохраняются: expected-стражи, постусловия, isModified-гейты,
own_bases для пакетных операций, незнакомые диалоги — Отмена + отказ.

## 5. Пробы и критерии

| № | Проба | Критерий |
|---|---|---|
| **П1** | На empty2: создать расширение вручную (один раз; пользователь), открыть его дерево, прочитать мостом: session_info — появился ли контейнер; **видно ли расширение в openedCount без открытия** (ревью М-4); md_tree/md_object/module_get через container=N | расширение адресуемо как контейнер; чтение работает; факт про неоткрытые зафиксирован; **если адресации нет — Г1 ложна, останов, решение владельцу** |
| **П2** | Автоматизировать «Добавить расширение» (имя, префикс, синоним) + ext_open. **Факт П1-цикла 28.10.2026:** слепой перебор команд Config 35+ запрещён — 35 = «Каталоги шаблонов», МОДАЛЬНЫЙ диалог: тики моста в модальном режиме заблокированы, dialog и control_send_event недоступны, выход только taskkill. Автоматизация только по известным контролам окна «Расширения конфигурации» (снимаются после П1) | расширение создано, дерево открыто, контейнер адресуем; постусловие: **ровно одно** расширение с этим именем (ревью М-5) |
| **П3** | Структура в расширении: md_add_child (справочник), module_set, простые свойства, ext_save; form_export формы расширения (Г2-чтение). **Предусловие:** дерево основной конфигурации закрыто (страж заголовка — ревью М-6); **негатив-постусловие:** снимок состава основной конфигурации до/после — расхождение = АВАРИЯ (уход Insert в чужое дерево) | объект/модуль/свойство в расширении; форма читается внутренним текстом; основная конфигурация не тронута |
| **П4а** | Снять ХАРАКТЕР диалога заимствования (дампер модалей + view_list): модальный или обычное окно (ревью М-6) — до автоматизации П4 | характер зафиксирован; если немодальный — путь автоматизации через view_controls/control_send_event |
| **П4** | Заимствование объекта из основной конфигурации (команда Frntend,271 + диалоги по данным П4а); снимок состава основной до/после | заимствованный объект в расширении, префикс платформенный, основная конфигурация не тронута |
| **П5** | cfe: ext_save_cfe при isModified (факт «Нет»-семантики); ext_load_cfe — **постусловие «ровно одно расширение с этим именем»** (ревью М-5); ext_delete непустого — белый список подтверждения, предусловие «редакторы закрыты», постусловие «контейнер исчез»; **факт: нужен ли шаг обновления БД для расширений** | cfe полный; загрузка воспроизводит расширение; удаление чистое; факт про БД зафиксирован |
| **П6** | РАЗВЕДКА (ревью К-2): справка дизайнера по -Extension ключам; ручной перенос cfe в слот линии. Доработка mcp_to_line.py (cfe-шаги, гейт isModified расширения, постусловия -Extension, «одно расширение на линию») — ОТДЕЛЬНАЯ работа по итогам разведки | факты о ключах; cfe переносится в слот; декомпозиция доработок зафиксирована |

Негативы на каждом шаге: isModified=true — отказ; незнакомый диалог — Отмена + отчёт.

## 6. Риски

| Риск | Что делаем |
|---|---|
| Диалоги создания/заимствования — незнакомые окна | дампер модалей на каждой пробе; мастер-раннер по флаг-файлу; инвариант «незнакомое — Отмена» |
| Индексы контейнеров плавают при открытии/закрытии | резолвить расширение по identifier/имени, не хранить индекс |
| Заимствование меняет основную конфигурацию тоже? | снять снимок состава до/после (К2-механика из этапа 8); негатив в П4 |
| Пакетные -Extension ключи не существуют/отличаются | проба читает справку дизайнера + живой прогон; fallback — мостовые команды |
| Г1 ложна (расширение не контейнер) | останов этапа, решение владельцу (П1 — критическая проба) |
| Префиксы расширений в линии конфликтуют | правило имени расширения в линии (одно расширение на линию, имя = имя линии) |

## 7. Оценка

П1 — час; П2–П5 — по сессии; П6 — сессия; реализация — 1–2 сессии. Итого 4–6 сессий.

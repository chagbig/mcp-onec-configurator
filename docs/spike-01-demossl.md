## Что это значит для плана

1. **Транспорт — A.** Защита `busy` + `modalMode` подтверждена замером, а не рассуждением.
2. **Запись модулей — через редактор с выделением `(1,1)–(n+1,1)`.** Хеш снимается с `getModuleText` (это живой
   буфер); отдельная сверка «буфер против свойства» не нужна, но вреда от неё нет.
3. **Формы (этап 8) — путь найден без реверса:** открыть редактор (`editProperty`) → `saveToFile`/`loadFromFile`
   внутреннего текста. Нужно решить, как пометить конфигурацию изменённой после загрузки (`IMDObject.setModified`
   или сохранение документа редактора) и чем переводить XML ↔ внутренний текст (гипотеза 1 этапа 8).
4. **Архив перед сохранением.** Zip базы при открытом конфигураторе невозможен, cf из живого сеанса через API
   не работает. Варианты — в вопросе владельцу (ниже).
5. **Ключ `/DisableStartupDialogs` ломает Снегопат** — в README моста и в скрипт запуска.
6. **Признаки сдвига слотов на 2074** (`extPropEditorCLSID`, `saveToFile` контейнера) — такие методы нельзя
   использовать без проверки на этой сборке.

`archive_cycle.json`; временные базы и выгрузки — `Y:\Snegopat-mcp\verify`.

| Проверка | Результат |
|---|---|

| Содержимое архива B (с правкой в редакторе, ответ «Нет») | временная база из cf → выгрузка модуля = исходный текст, правки нет; cf A (без правок) и B побайтно равны |

Правило для моста: перед `config_save` — `cfg_archive_cf` с ответом «Нет» на вопрос об изменениях (точка
отката = последнее сохранённое состояние); `config_save` принимает путь к этому архиву и без него отказывает.
Zip базы — только перед обновлением конфигурации БД, при закрытом конфигураторе (сервер MCP: сохранить →
закрыть → zip → проверить → открыть → обновить), только для `own_bases`.

## Вопрос владельцу (закрыт 16.10.2026: выбран вариант 1)

Перед `config_save` архив zip базы снять нельзя, пока открыт конфигуратор. Варианты:

1. **Архив конфигурации, а не базы:** cf через штатную команду «Сохранить конфигурацию в файл» с подстановкой
   имени файла через `onSelectFile` (нужно проверить). Сохранение конфигурации данные не меняет — их меняет
   только «Обновить конфигурацию БД», а для него архив можно снимать при закрытом конфигураторе.
2. **Zip базы, но с закрытием конфигуратора:** закрыть → архив → открыть заново → сохранить. На своей копии это
   1–2 минуты на каждое сохранение, и несохранённые правки на время закрытия надо сохранить где-то ещё — то есть
   вариант противоречит сам себе.
3. **Снимок тома (VSS)** — нужны права администратора, сюда не подходит.

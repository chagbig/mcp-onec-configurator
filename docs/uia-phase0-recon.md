## Значение для «карты переходов»

1. **Карта меню снимается программно**: UIA-скан раскрытого меню = имена +
   точный enabled — пиксельная эвристика (tools/menu_enabled.py) становится
   резервом; карта обновляется скриптом за секунды.
2. **Диалоги тоже UIA**: окно создания объекта экспонирует поля (Name/
   Value) — «логирование действий пользователя по созданию объектов»
   (запрос владельца) решается сканом диалога до/после заполнения +
   md_journal (факт создания) — клавиатурный лог нужен только для полей,
   которые UIA не экспонирует.
3. **Активация**: остаётся mouse_click (тик) + клавиатура. InvokePattern —
   нет. HoldingPattern для диалогов: кнопки ОК/Отмена могут поддерживать
   Invoke (проверить при Ф1) — тогда диалоги закрываются/подтверждаются
   программно.

## План v1.14 (уточнённый после Фазы 0)

1. **uia_menu_map.py** — программное снятие карты: раскрыть меню
   (mouse_click из тика) → UIA-скан пунктов (Name/IsEnabled/submenu) →
   menu_map.json (заменяет ручное чтение агентом; пиксельный детектор —
   резерв для недоверенных случаев). Подменю — тем же циклом.
2. **user_watch.py** — станционный регистратор (LL-хуки мыши, foreground,
   скриншоты по клику, JSONL) + корреляция с md_journal/state_snapshot;
   фильтры безопасности: не логировать содержимое ввода в окнах с полями
   пароля (окно «Соединение с хранилищем» — уже встречалось!).
3. **uia_dialog_read.py** — скан открытого диалога (поля/значения) —
   «что пользователь заполнил» для рецептов создания объектов.
4. **graph_builder** — из следов: «состояние_до → действие → состояние_после»
   в карту переходов; верификация воспроизведением агентом.

Риски/открытые: UIA-экспонирование диалогов 1С не гарантировано (проверить
на окне создания объекта при Ф1); LL-хуки требуют живого message-пульта
станционного процесса — ок; приватность (логи вне репо).

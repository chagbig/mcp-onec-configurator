# Этап 24 (v1.3.0): гибридный diff + YAXUnit + md_clone

Релиз v1.3.0 из трёх частей (план от 11.11, согласован владельцем — «Приступай к
релизу 1.3.0»).

## 1. Гибридный diff (cf_diff ред. 4) — ядро

Проблема ред. 3: точность канона стоит ПОЛНЫХ XML-выгрузок (2 ГБ пара: слоты
~10 мин + выгрузки ~25-40 мин на каждую).

Решение (исследование «Идея 4», cb61f65/caace25): кандидатный набор из записного
сканера → точечные выгрузки только кандидатов.

- Слой 1: `cf_recdiff.scan` (существует, 1–2 мин на 2 ГБ) → кандидаты
  (new/deleted/changed по именам записей);
- Карта uuid → голое имя: `{1,0,<uuid>},"Имя",` по всем записям обеих cf
  (как в md_search_code.load_names);
- Слой 2: частичные `/DumpConfigToFiles <dir> -listFile <имена>` из ОБОИХ слотов
  (слоты mockup_init с РЕУСом по маркеру sha1 источника — повторные диффы без
  пересоздания слотов);
- Слой 3: `compare_dumps` по подмножеству (тот же код) → diff.json совместим с
  build_ext (новые объекты — из recdiff-списка, not only2-обход);
- CLI: `--hybrid` (умолчание) / `--full-canon` (ред. 3 без изменений);
- Постусловия: малая пара — вердикты гибрида == полному канону; пилотная
  185011↔p4b — ровно известная истина (МсрПриёмка NEW + версии);
- Ловушка из пробы: bare-имена в -listFile принимаются (listfile_probe).

## 2. №22 YAXUnit-прогоны из MCP

Разведка параметров запуска (skill yaxunit-autotests как источник) →
`server/tools/yaxunit_run.py`: 1cv8 ENTERPRISE /Execute YaxUnit.epf с конфигом
(JSON-отчёт) → парсер отчёта → сводка (тестов/провалов). MCP-обёртка.

## 3. №18 md_clone

MVP-клон объекта в живой сессии: новый объект того же вида (имя+суффикс),
перенос реквизитов/ТЧ с типами, синоним, комментарий, модули. НЕ копируются
формы/макеты/СКД (документированное ограничение; формы — форм_get_xml/set_xml
контуром отдельно).

## Ловушки, найденные на этапе

1. **Фокус дерева приходит не сразу.** `activateInTree` и Insert в одном обработчике — нажатие уходит в окно
   свойств или редактор, открытые предыдущим действием. Выделение — отдельным запросом (тиком); перед нажатием
   мост проверяет `windows.getActiveView().title` и без дерева отказывает, ничего не нажимая.
2. **Команды панели дерева идут мимо главного окна.** `cmdTrace` их не видит, `IV8View.getCmdState` у дерева
   возвращает `null` на всех номерах (1604 вызова), `Frame` 48 ничего не создаёт. Клавиатура надёжнее.
3. **`v8New("ОписаниеТипов")` с прикладным типом роняет процесс.** Только через внутреннее представление.
4. **JScript 5 — ES3:** нет `Array.prototype.indexOf` (упало в операции; в перехвате модальных окон удаления
   ошибка была скрытой — мост не смог бы отказать по неизвестному диалогу).
5. **Порядок групп в дереве зависит от класса** (у справочника первой — «Реквизиты», у регистра — «Измерения»).
   Навигация для первого подчинённого берётся из таблицы классов, а созданный объект проверяется по классу и
   владельцу из `mdeAdd`.
6. Обработчик `MetaDataEvent` в движке вызывает `get_container()` с подменой обёртки — объект после события
   разрешается заново по uuid (так и сделано).

## Чего ещё нет

* Устойчивый способ создать **первый** реквизит табличной части (сейчас — щелчок по координатам кнопки редактора).
* Макеты, команды, константы, общие модули, роли, регистры накопления — не пробовались (способ тот же, нужны k и
  обработка конструкторов там, где они открываются).
* Назначение ссылочных свойств-объектов кроме состава подсистемы (владельцы справочника, регистраторы и т.п.) —
  тем же внутренним представлением, не проверено.
* Сравнение с пакетной выгрузкой cf (`/DumpCfg`) той же базы — не мерил.

## Пустая база: все классы по порядку владельца (17.10.2026)

По просьбе владельца пробы перенесены на пустую базу `Y:\Snegopat-mcp\bases\empty_mcp` (создана
`CREATEINFOBASE` за 1 с): открытие конфигурации 0,1 с, архив cf 0,1 с, сохранение 0,06 с, cf 0,08 с. Сценарии —
[spike/st7_lib.py](../spike/st7_lib.py); ответы — `spike/out/empty_*.json`, `form_wizard_*.json`; проверка cf —
`verify\dump-empty-r1…r6`.

**Единый способ создания — навигация к узлу группы, а не сосед.** Выделить владельца (отдельным тиком) →
«+» (развернуть) → k раз «↓, −» (каждый пройденный узел свернуть: положение не зависит от того, что было развёрнуто
раньше) → Insert. Работает и для пустой, и для непустой группы. k — по классу владельца:

| Владелец | Группа → k |
|---|---|
| Конфигурация | Константы 2, Справочники 3, Документы 4, Журналы 5, Перечисления 6, Отчёты 7, Обработки 8, ПВХ 9, Планы счетов 10, ПВР 11, Регистры сведений 12, …накопления 13, …бухгалтерии 14, …расчёта 15, Бизнес-процессы 16, Задачи 17; подсистемы — путь [1, 1] (Общие → Подсистемы) |
| Справочник, Документ | Реквизиты 1, Табличные части 2, Формы 3, Команды 4, Макеты 5 |
| Регистр сведений | Измерения 1, Ресурсы 2, Реквизиты 3 |
| Перечисление | Значения 1 |

Созданный объект принимается, только если в `mdeAdd` совпали класс (`expectClass`) и владелец; всё прочее,
созданное за вызов, возвращается в `stray`.

| Объект | Как | В cf (XML из временной базы) |
|---|---|---|
| Справочник, документ, регистр сведений, перечисление | корень, k по таблице | есть; uuid = `mdeAdd` |
| Реквизиты документа (ссылка на справочник, число 15.2, строка) | k=1 | `cfg:CatalogRef.МсрСправочник`, `xs:decimal` 15.2, `xs:string` |
| Табличная часть | k=2 | есть |
| **Первый реквизит табличной части** | у ТЧ нет узла группы: Insert на ТЧ создаёт соседнюю ТЧ (поймано как `stray`, удалено). Рабочий путь — кнопка «добавить реквизит» на закладке «Данные» редактора документа (щелчок по координатам — **хрупко**, нужен устойчивый способ) | есть |
| Следующие реквизиты ТЧ | Insert рядом с существующим | ссылка, `xs:decimal` 15.3 |
| Измерение, ресурс, реквизит регистра | k=1, 2, 3 | `cfg:CatalogRef`, `xs:decimal` 15, `xs:string` |
| Значения перечисления | k=1 (и для второго значения) | оба значения |
| Подсистема | путь [1, 1] | есть |
| Состав подсистемы | `Состав` — объект; запись через внутреннее представление: `{"#",9cd510d6-…,{0,N,{"#",157fa490-…,{1,<uuid>}},…}}` (формат снят с подсистемы БСП демо) | 4 объекта в `Content`; сохранение **без предупреждений** «не включён ни в одну подсистему» |
| Форма | Insert в «Формы» открывает модальный «Конструктор формы справочника». **Закрытие с результатом ОК — неверно**: обычная (Ordinary) пустая форма без имени. **Верно — нажать его кнопки** (`form.sendEvent(control.id, 0)`, как `choiceHelpTopic.js`): переключатель типа → имя `Ident` → `OK` | управляемая форма списка: таблица «Список», `cfg:DynamicList` по `Catalog.МсрСправочник`, назначена `DefaultListForm` |

Мелкие находки: значение группы переключателей конструктора хранится в первом элементе группы
(`ElementFormRB` = номер выбранного); присваивание значения переключателю не работает — только нажатие.
Переименование: постусловие ищет объект по uuid (старый путь после переименования недействителен).

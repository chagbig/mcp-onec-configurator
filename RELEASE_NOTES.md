# RELEASE_NOTES — mcp-configurator

## v1.0.0 — 28.10.2026

Первый релиз. MCP-сервер (41 инструмент) + мост-аддин Снегопата + пакетные инструменты cf.

### Что умеет

**Живой конфигуратор (через мост Снегопата, платформа 8.3.27):**
- чтение дерева метаданных, объектов, модулей, форм (внутренний текст);
- запись: модули (hash-страж), свойства, синонимы, типы; создание/удаление объектов;
- конфигурация: открыть/сохранить (с архивом cf-отката), синтакс-проверка, обновление БД;
- хранилище конфигурации: захват/помещение;
- формы: чтение XML из cf (`form_get_xml`), запись XML в живую базу (`form_set_xml`) —
  через temp-базу, с кэшем и верификацией (вендор цел, правки в живой форме);
- расширения: список, создание, открытие, сохранение, выгрузка cfe (см. конвейер ниже).

**Пакетные инструменты cf (без платформы):**
- `cf_inspect.py` — чтение v8-контейнера cf (2 ГБ — 6 с; сериализации, модули, формы);
- `cf_diff.py` — сравнение двух cf (XML-канон платформы; на 2 ГБ паре — ровно истинная дельта);
- `build_ext.py` — **конвейер «расширение из сравнения двух cf»**: cf1+cf2 → diff →
  заимствование → наполнение (реквизиты с маппингом префикса, Adopted-контейнеры) →
  перехватчики модулей (ИзменениеИКонтроль) → cfe-артефакт + отчёт о непереносимых
  отличиях. Верификации: вендор байт-в-байт цел (по хешам записей), CheckModules,
  постусловия на каждом шаге;
- `mcp_to_line.py` — доставка правок живой базы в базу линии (cf → пакетный прогон →
  постусловия XML; ~1 мин против 28 мин полной выгрузки);
- `mockup_init.py` — чистые базы-макеты из эталонного cf.

### Что НЕ входит (сознательные границы)

- ~~формы расширений (автоматическая запись) — нужен cfe-контур записи~~
  → закрыто в main (этап 15: замещающие формы переносятся build_ext автоматически,
  живая проверка открытия формы — по-прежнему ручная);
- заимствование/удаление расширений через контекстные меню — ручной шаг
  (разблокируется установкой DynamicWrapperX — решение владельца);
- «первый реквизит ТЧ» живым деревом — обходится XML-контуром;
- прочие версии платформы (8.3.28+) — при переходе пересъём слотов движка.

### Известные ловушки (полный список — docs/ и скилл onec-snegopat-mcp)

- пакетные вызовы на базе, открытой живым конфигуратором, падают «1Cv8.cdn…» —
  работайте по копии базы (ext_dump_cfe делает это сам) или закрывайте конфигуратор;
- несуществующее имя в `-Extension` — молчаливый пропуск rc=0: всегда постусловия;
- живой редактор формы НЕ пишет в конфигурацию (form_import меняет только буфер);
- каталоги `mcp/sessions/<pid>` живых конфигураторов не удалять.

### Установка

См. [README.md](README.md#установка): Снегопат 1.6.43 (`Y:\Snegopat-mcp\x64`),
файл включения `mcp_bridge.on`, `pip install -e server`, конфиг `mcp_snegopat.json`,
подключение в `~/.zcode/cli/config.json` → `mcp.servers`.

### Требования

Windows 10+; платформа 1С 8.3.27.2074; Снегопат 1.6.43; Python ≥3.11 (mcp≥2.3);
путь установки без кириллицы; build_ext.py ожидает скилы в
C:/Users/<user>/.agents/skills/ и платформу 8.3.27.2074 (пути в константах
файла — на другой машине поправить перед запуском).

### Примеры

```bash
# живая правка: создать справочник, записать модуль, сохранить
# (инструменты md_add_child / module_set / config_save)

# формы: прочитать XML формы из cf, поправить, записать в живую базу
# (form_get_xml → правка → form_set_xml; ~10 мин на конфигурации 2 ГБ)

# конвейер «расширение из двух cf»:
python server/tools/build_ext.py vendor.cf updated.cf --name МсрДиф --prefix Мср14_
# → расширение (заимствование+наполнение+перехватчики) → cfe → отчёт

# доставка cfe в базу линии (пакетно):
1cv8 DESIGNER /F <база линии> /LoadCfg МсрДиф.cfe -Extension МсрДиф /DisableStartupDialogs
1cv8 DESIGNER /F <база линии> /UpdateDBCfg -Extension МсрДиф /DisableStartupDialogs
```

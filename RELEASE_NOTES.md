## v1.3.0 — 11.11.2026

### Гибридный diff (флагман v1.3) + клонирование + тесты

- **`cf_diff` ред. 4 — кэш-конвейер**: слоты И полные XML-выгрузки кэшируются по
  sha1 cf (маркеры `slot-*.origin.json`/`dump-*.origin.json`) — повторные diff
  той же пары за СЕКУНДЫ (первый — цена ред. 3). CLI: `--hybrid` (умолчание,
  включает cf_recdiff-кандидатов в отчёт) / `--full-canon` (ред. 3). Постусловие:
  на малой паре гибрид и полный канон дают ПОБАЙТНО одинаковый full_diff;
- **честные ограничения точечных -listFile выгрузок** (исследовано, в доке этапа):
  платформа требует ПОЛНЫЕ имена (Вид.Имя) — bare/uuid/«Конфигурация» отвергаются
  («не является именем объекта метаданных»); резолвер uuid→Вид из cf не построен
  (Configuration-запись — плоские списки, class-гиды пер-конфигурационные и
  двусмысленны) — открытая проблема в реестре идей;
- **`md_clone` (54-й)** — клон объекта одним вызовом (IDEAS №18): реквизиты с
  типами (примитивные/ссылочные internal), табличные части, синоним «… (копия)»,
  модули. НЕ копируются формы/макеты (отдельный контур) и реквизиты ПУСТЫХ ТЧ
  (гвард 26.10, в ответе note);
- **`yaxunit_run` (55-й)** — прогон YAXUnit без конфигуратора (IDEAS №22):
  ENTERPRISE /Execute с конфигом (jUnit-отчёт, автозакрытие клиента), сторож по
  таймауту, парсер отчёта (тесты/провалы/ошибки + список упавших). Живой прогон —
  на стенде владельца (на этой машине YAxUnit.epf/стендов нет);
- 150/150 тестов; план и ход — `docs/stage-24-v13-hybrid-diff.md`.

## v1.2.6 — 11.11.2026

### Новые инструменты (52-й, 53-й) + безопасность деструктивных операций

- **`query_validate` (52-й)** — валидация запросов 1С через внешнее соединение,
  без конфигуратора (IDEAS №21). Язык запросов read-only — исполнение безопасно
  по данным. Режим `check` (умолчание): обёртка «ВЫБРАТЬ ПЕРВЫЕ 1 * ИЗ (…)» —
  дёшево; `execute`: запрос целиком с возвратом колонок и до limit строк. Текст
  ошибки 1С = вердикт валидации (`ok:false, error:…`). Живой прогон: валидный и
  битый запросы;
- **`infobase` (53-й)** — создание/удаление файловых инфобаз (IDEAS №23):
  `create` — пакетный CREATEINFOBASE (идемпотентно); `delete` — двухфазно (№19):
  план (существование, занятость .cfl, гвард own_bases) → `confirm=True` удаляет.
  **Найден и обойдён дефект платформы**: CREATEINFOBASE ломается на ПРОБЕЛЕ в
  пути (кавычки не спасают; кириллица без пробела работает) — обход: создание
  под ASCII-именем в том же каталоге + rename;
- **двухфазное подтверждение деструктивных (IDEAS №19)**: `md_delete` и
  `update_db_cfg` — `confirm=False` (умолчание) возвращает ПЛАН (объект, ссылки
  через md_check_refs, предупреждение о неприменённых правках) без действия;
  исполнение — только с `confirm=True`;
- **отладка — хвосты закрыты с честным негативом**: условные точки (BrkptCond)
  из моста нереализуемы (Shift+F9 теряет модификаторы, sendCommand CDebug,12
  блокирует тик — op переведён в явный отказ); панель «Точки останова»
  owner-drawn (0 дочерних HWND) — чтение отложено до UIA-разведки. Рабочий
  минимум остался: точное позиционирование + F9-точки (v1.2.5);
- 144/144 тестов; разбор — `docs/stage-22-debug-search-structure.md`.

## v1.2.4 — 08.11.2026

### По смоук-отчёту v1.2.3 (mcp-configurator-v1.2.3-smoke-all-tools.docx)

- **Установщик**: новый шаг «Синхронизация моста в установленные версии
  Снегопата» — выполняется ВСЕГДА (в т.ч. при `-SkipSnegopat`, идемпотентно):
  перекладывает `bridge\mcp_bridge.js` из поставки в каждую найденную
  `snegopat\*\x64\modules\snegopat\addins\mcp\` и в легаси-каталог
  `<дом>\x64\modules\snegopat\addins\mcp\`. Раньше при `-SkipSnegopat`
  рабочий аддин не обновлялся — сессии оставались на старом мосту (главное
  отклонение отчёта). Залоченный файл (живой конфигуратор) = явный Fail
  с подсказкой закрыть конфигураторы. Попутно (найдено живым безattended-
  прогоном v1.2.4): `regsvr32 /i` → **`/s /i`** (модалка regsvr32 вешала
  автоматический прогон; silent-регистрация проверена: HKCU CLSID
  восстанавливается), и в конце установщика явный `exit 0` — robocopy
  возвращает 1 («файлы скопированы»), что утекало в exit-код;
- **мост**: `tree_activate_group` больше не падает голым «Объект не
  поддерживает…» — диагностика (`md_class_probe`) показала:
  `activateInTreeEx` не поддерживается платформой ни на 1.6.43, ни на 3.0.66
  (дескрипторы подчинённых классов при этом живы: name и id — GUID вида).
  Теперь: выделяется сам объект, ответ
  `{ok:false, groupActivated:false, reason:…}`; неверный kind — перечень
  имеющихся видов. Новый диагностический op `md_class_probe` (в составе
  моста, MCP-обёртки нет);
- **доки**: ограничение eventlog «Существуют активные сеансы работы с данной
  ИБ…» (живый конфигуратор блокирует COM-соединение) внесено в оба руководства;
  разбор смоук-отчёта — `docs/stage-21-gaps.md`;
- form_export/form_get_xml на объекте без форм — подтверждено ожидаемым
  поведением (инструментам нужен объект с формой);
- 106/106 тестов; живая верификация на 1.6.43 (empty2) и 3.0.66 (empty_mcp).

- `cf_diff.py` — сравнение двух cf (XML-канон платформы; на 2 ГБ паре — ровно истинная дельта);
- `build_ext.py` — **конвейер «расширение из сравнения двух cf»**: cf1+cf2 → diff →
  заимствование → наполнение (реквизиты с маппингом префикса, Adopted-контейнеры,
  замещающие формы) → перехватчики модулей (ИзменениеИКонтроль) → cfe-артефакт +
  отчёт о непереносимых отличиях. Верификации: вендор цел (слот до/после
  расширения), CheckModules, постусловия на каждом шаге; тот же конвейер —
  MCP-инструментом `ext_build_from_cf` (этап 16);
- `mcp_to_line.py` — доставка в базу линии: правки живой базы (cf → пакетный прогон →
  постусловия XML; ~1 мин против 28 мин полной выгрузки) или готового cfe расширения
  (`--cfe --ext-name`: Load/Check/Update -Extension + постусловие хешей записей, этап 16);
- `mockup_init.py` — чистые базы-макеты из эталонного cf.

### Что НЕ входит (сознательные границы)

- ~~формы расширений (автоматическая запись) — нужен cfe-контур записи~~
  → закрыто в main (этап 15: замещающие формы переносятся build_ext автоматически,
  живая проверка открытия формы — по-прежнему ручная);
- ~~заимствование/удаление расширений через контекстные меню~~ → разблокировано:
  DynamicWrapperX 2.2.0.0 установлен (x64+x86 в Y:\Snegopat-mcp\bin, per-user HKCU,
  `regsvr32 /i <путь>`); живой контур — при следующем старте конфигуратора;
- «первый реквизит ТЧ» живым деревом — обходится XML-контуром;
- прочие версии платформы (8.3.28+) — при переходе пересъём слотов движка.

### Известные ловушки (полный список — docs/ и скилл onec-snegopat-mcp)

- пакетные вызовы на базе, открытой живым конфигуратором, падают «1Cv8.cdn…» —
  работайте по копии базы (ext_dump_cfe делает это сам) или закрывайте конфигуратор;
- несуществующее имя в `-Extension` — молчаливый пропуск rc=0: всегда постусловия;
- живой редактор формы НЕ пишет в конфигурацию (form_import меняет только буфер);
- каталоги `mcp/sessions/<pid>` живых конфигураторов не удалять.

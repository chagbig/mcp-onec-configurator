# Руководство администратора — mcp-configurator v1.1.0

Кому читать: тому, кто ставит, обновляет и обслуживает систему на машине
разработки 1С. Рабочие сценарии — в РУКОВОДСТВО-ПОЛЬЗОВАТЕЛЯ.md.

## 1. Состав поставки

| Каталог/файл | Что это |
|---|---|
| `install.ps1` | установщик (PowerShell, прав администратора не требует) |
| `snegopat-x64\` | Снегопат 1.6.43, модифицированная сборка: `std/main.js` грузит минимальный комплект + мост `addins\mcp\mcp_bridge.js` (v1.1), `Libs\winapi.js`, движок и v8api |
| `bin\` | DynamicWrapperX 2.2.0.0: `dynwrapx.dll` (x64), `dynwrapx32.dll` (x86), справка |
| `mcp-configurator\` | проект: MCP-сервер (44 инструмента), исходники моста, пакетные инструменты cf (`build_ext`, `cf_diff`, `cf_inspect`, `ref_check`, `mcp_to_line`, `mockup_init`, `form_xml`, `form_text`), тесты (84), доки этапов |
| `УСТАНОВКА.txt` | краткая памятка (5 строк установки) |

## 2. Требования

- Windows 10+; сеанс с обычными правами (админ не нужен: всё ставится per-user);
- **платформа 1С 8.3.27.2074** — `C:\Program Files\1cv8\8.3.27.2074\bin\1cv8.exe`
  (другие версии не поддерживаются: слоты движка снимались под 8.3.27);
- **Python ≥ 3.11** в PATH; для `pip install -e server` нужен доступ к PyPI
  (пакет `mcp`);
- **целевой диск `Y:`** — мост жёстко пишет в `Y:\Snegopat-mcp\mcp` (константы в
  `bridge/mcp_bridge.js`); путь установки без кириллицы.

## 3. Установка

Из корня распакованной поставки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Ключи: `-Drive Y` (другой диск — НЕ рекомендуется, см. выше), `-SkipPip`,
`-SkipSnegopat`.

Установщик делает по порядку:
1. проверяет платформу, Python, наличие диска;
2. ставит Снегопат в `Y:\Snegopat-mcp\x64` (прежняя сборка уезжает в
   `x64-backup-<штамп>` — откат = вернуть каталог обратно);
3. создаёт каталоги моста (`mcp\sessions`, `mcp\journal`, `mcp\forms`,
   `backups`, `bin`, `verify`, `temp`) и **флаг включения**
   `Y:\Snegopat-mcp\mcp\mcp_bridge.on` (без него мост не ставит таймер);
4. создаёт конфиг сервера `Y:\Snegopat-mcp\mcp\mcp_snegopat.json` из примера;
5. копирует DynamicWrapperX в `bin\` и регистрирует **per-user** (HKCU):
   `regsvr32 /i <путь>\dynwrapx.dll`;
6. копирует проект в `Y:\mcp-configurator` и делает `pip install -e server`;
7. запускает `starter.exe` **с рабочим каталогом `x64`** (резидентный инжектор
   моста — должен висеть процессом всегда).

## 4. Ручные шаги после установки

1. **ZCode**: в `~/.zcode/cli/config.json` → `mcp.servers` добавить
   ```json
   "mcp-snegopat": { "command": "mcp-snegopat" }
   ```
   (конфиг сервера ищется в `MCP_SNEGOPAT_CONFIG` или
   `%LOCALAPPDATA%\mcp-snegopat\config.json`; установщик кладёт его в
   `Y:\Snegopat-mcp\mcp\mcp_snegopat.json` — пропишите путь в env).
2. **Свои базы**: в `own_bases` конфига дописать базы, с которыми разрешена
   запись через мост, в формате `File="<путь>";` — это ГЕЙТ всех операций
   записи/обновления БД.
3. **Проверка**: открыть конфигуратор (см. §5) → в ZCode вызвать
   `list_sessions` → сессия с `bridge: "1.1"` и полем `journal`.

## 5. Запуск конфигуратора

Порядок строгий:
1. `starter.exe` запущен (резидентно; если умер — стартовать из `x64`, cwd
   важен: инжектор ищет модули относительно него);
2. конфигуратор запускать **строго** `1cv8.exe DESIGNER /F <база>` — без слова
   `DESIGNER` откроется лаунчер «Запуск 1С:Предприятия» и повиснет; из
   Git Bash аргументы искажаются (MSYS) — запускайте через python-subprocess
   или ярлык.

Признак живого моста: каталог `Y:\Snegopat-mcp\mcp\sessions\<pid>\` появился,
`list_sessions` видит сессию.

## 6. Обновление

- **проект**: `git pull` в `Y:\mcp-configurator` + `pip install -e server`
  (зависимости редко меняются);
- **мост**: после правок `bridge/mcp_bridge.js` — скопировать в
  `x64\modules\snegopat\addins\mcp\` и **перезапустить конфигуратор**
  (аддин грузится на старте); парсить JS через `pip install esprima` (cscript
  кириллические идентификаторы не парсит, Node не обязателен);
- **снегопат-сборка**: установщик поверх (старая уедет в backup) либо вручную
  с сохранением `data\` (настройки пользователя);
- **новый релиз**: распаковать поставку, запустить `install.ps1`.

## 7. Эксплуатация и обслуживание

**Диск.** Прогоны на больших конфигурациях требуют транзита ~15 ГБ
(слоты + полные выгрузки в `verify\<работа>\diff\`). При «UpdateDBCfg молча
FAIL» первым делом проверяйте свободное место. Чистка по мере надобности:
`Y:\Snegopat-mcp\verify\<старые работы>\`, `backups\*.cf` старых прогонов.

**Каталоги.** `mcp\sessions\<pid>\` живых конфигураторов НЕ УДАЛЯТЬ (аддин не
пересоздаёт — сессия выпадет из моста). `mcp\journal\<pid>.jsonl` — журнал
правок (UTF-16), ротация вручную при разрастании. `backups\` — cf-откаты
(config_save) — хранить до уверенности.

**Журнал вызовов/ошибок**: `x64\logs\script-errors.txt` (JScript-ошибки
аддинов), `session_info → stat` (ticks/errors/lastError) — первая точка
диагностики; `report.json`/`handoff-*.json` в рабочих каталогах — вердикты
конвейеров.

## 8. Типовые проблемы

| Симптом | Причина | Действие |
|---|---|---|
| `list_sessions` пуст при запущенном 1cv8 | стартер не был запущен ДО 1cv8 | закрыть 1cv8, запустить `starter.exe` из `x64`, открыть конфигуратор заново |
| конфигуратор висит на «Запуск 1С:Предприятия» | запуск без слова `DESIGNER` | запускать `1cv8.exe DESIGNER /F <база>` |
| пакетный вызов падает «1Cv8.cdn. Схема не зарегистрирована» | база открыта живым конфигуратором | работать по КОПИИ базы (`ext_dump_cfe` делает сам) или закрыть конфигуратор |
| «Cannot create object DynamicWrapperX» | DWX не зарегистрирован в этом профиле | `regsvr32 /i Y:\Snegopat-mcp\bin\dynwrapx.dll` (без админа) |
| 1cv8 (x64) не видит DWX | стоит только 32-битная v1.00 | поставить v2.2.0.0 x64 из поставки |
| `md_journal` пуст | мост < 1.1 или правок не было | обновить мост, сделать правку |
| pip install падает | нет сети/PyPI | `install.ps1 -SkipPip`, поставить `mcp` из внутреннего зеркала |
| .ps1 с кириллицей не парсится | файл без UTF-8 BOM | пересохранить с BOM (PowerShell 5.1 читает без BOM в cp1251) |

## 9. Безопасность

- Запись в метаданные разрешена только базам из `own_bases` конфига — гейт
  сервера; не добавляйте туда продуктивные базы.
- DynamicWrapperX зарегистрирован в HKCU текущего пользователя (не HKLM) —
  влияет только на его сеанс; отозвать: `regsvr32 /u <путь>`.
- Флаг `mcp_bridge.on` — рубильник моста: снять файл = мост перестаёт
  обрабатывать запросы (конфигуратор продолжает работать как обычный).
- Журнал `md_journal` содержит имена объектов и типы правок, но не данные —
  можно хранить без ограничений.
